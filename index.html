Worth testing

B70 fork's big SYCL prefill gains are still unreviewed and not upstream

Worth an A/B on a spare build, not production

Developer valarauca's B70-specific llama.cpp branch is still the largest claimed jump in SYCL performance on Battlemage. It matters to every B70 owner because it targets the slowest part of the card's experience: reading long prompts. Nothing moved this week. The pull request is still open in valarauca's own fork, with no reviewers and nothing submitted to the main llama.cpp project.

Some context. Stock SYCL builds pick fp16 or fp32 matrix maths at compile time, and the default fp32 path never touches the B70's matrix units (XMX). The branch detects the card's family at startup and switches to fp16 by itself. The author reports this alone took an 8B model's prompt reading from about 1,066 to 4,975 tokens per second in a default build. Across the full branch, the author reports Qwen3.8-27B at Q4_0 reading a 512-token prompt about 5.5 times faster than master (249 to 1,368 tokens per second). Generation barely changes on Q4_0, but rises about 56% on the popular UD-IQ4_XS quant, where reworked low-bit kernels remove a bottleneck.

Worth testing

MTP still slows SYCL decoding, and Vulkan has closed the gap

MTP lets a model guess several tokens ahead with its own built-in draft head and then check the guesses in one pass. Model cards advertise it as roughly 1.5 to 2 times faster generation. On a B70 running llama.cpp's SYCL backend, several independent write-ups still find it often makes things slower.

The upshot — test before you enable. Benchmark MTP on your own model and backend before leaving it on, and compare outputs as well as speed. If your work is mostly short prompts, Vulkan on a current Mesa is now a fair option to try. For long prompts, stay on SYCL.

Risk watch

Distro compute-runtime 26.35 can break Battlemage, so pin what works

Intel has not posted a new compute-runtime release on GitHub since 26.31.39395.13 on 21 August. That release lists Battlemage at production quality. The risk sits elsewhere: distro packages are ahead of Intel's GitHub releases, and at least one is broken on Battlemage.

The upshot — regression risk to avoid. If your B70 runs on 26.31, pin it and skip distro upgrades of the compute stack until someone reports 26.35 working on a B70. If an upgrade has already broken sycl-ls, suspect the runtime before the kernel.

Plan ahead

Flash-Next on Arc stays a research project, on one card or four

Qwen3.8-Flash-Next is Qwen's 125B mixture-of-experts preview of the Qwen4 architecture. It also carries an extra 51B-parameter lookup table. It is the model many B70 owners want to run, and two public Arc efforts now publish measured results. Neither is something to switch to casually yet.

The upshot — plan for it, don't deploy it. A single B70 owner who wants to try this needs fast multi-drive NVMe and should treat the build as a research setup. Four-card owners have a credible vLLM path, but should keep MTP off and stay on the stable line.
